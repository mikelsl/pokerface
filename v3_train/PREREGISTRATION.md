- 场次键：`session_id`。

## 2. 特征

- `static_*` 和 `dynamic_*`（168 个）。`timing_duration` 在 v2 中恒为 5，timing 对照组标为 `degenerate_constant`，不拟合；`full` = static + dynamic。
- 预处理：中位数填补、标准化，只在训练折上拟合。

## 3. 主协议（只在独立场次 ≥ 8 时运行）

- 沿用 `riverlab/train.py` 的四份划分：seed=17，GroupShuffleSplit，按 `session_id` 分组；C ∈ {0.01, 0.1, 1}，依据 tune 集 log loss 选择；在 calibration 集上做 sigmoid 校准；阈值 0.5；final_test 只跑一次。
- 如果任何一份缺少某一类：**不换种子**。主协议记为"证据不足"，转到 §4。

## 4. 诊断协议：留一场次交叉验证（LOSO）

- 只在 §3 失败时运行，结果只作试点诊断，**不报告为准确率**。
- 外层：每次留出一个场次，用其余场次训练。
- 内层：在训练场次内部再做一次 LOSO，按合并后的 out-of-fold log loss 从 {0.01, 0.1, 1} 中选 C。不做校准（场次太少）；报告里写明概率未校准。
- 汇总：把外层所有 out-of-fold 预测合并，计算 balanced accuracy、ROC AUC、log loss、Brier、混淆矩阵。
- 零分布：在**场次内**打乱标签，重复 1000 次（seed=17），给出 AUC 和 balanced accuracy 的置换 p 值。
- 对照组：majority、static、dynamic、full，外加 **identity**（只用训练折中每个下注者的 bluff 比例，没见过的人用训练折的总体比例）。identity 对照用来衡量"认人"能解释多少。
- 选手混杂检查：分别报告 PLAYER_A 样本和非 PLAYER_A 样本的 out-of-fold 指标；如果 full 不比 identity 好，结论写成"无法和选手身份区分"。

## 5. 结论的写法

- "证据不足"是合法结论。
- 任何结果都写明：标签是摊牌牌力代理，不是意图；样本小，而且经过筛选；转播制作和选手重复都是混杂因素。

## 7. 补充（2026-11-05 21:30，main；项目负责人 2026-11-05 21:19 批准；只针对今后的新数据，此时还没有任何新样本，也没有新结果）

背景：调研见 `workspace-ops/work/pokerface/RELATED_WORK.md`。规模最大的同类研究（Geel，同一选手 207 个场次）发现只有下注本身有信号；Slepian 2013 发现推筹码的手臂动作才有信号。下面三项都**加在** §3/§4 之上，不改变原有的主分析。

### 7.1 下注上下文对照（context）

- 特征只有 3 个，都只依赖下注本身，不依赖画面：
  - `is_raise`（action == raise）；
  - `multiway`（active_opponents > 1）；
  - `log_amount_rel`：log(amount / 同一场次所有样本 amount 的中位数)。只用金额，不用标签，留出的场次也用它自己的中位数。
- 新数据如果记录了 `pot_before_bet`，再加 `log(amount / pot_before_bet)`。只有当全部样本都有这个字段时才加，否则不加。
- 对照组：`context`（单独）和 `context+full`。用法和其他对照组相同（§3 或 §4）。
- 增量检验：统计量 = AUC(context+full) − AUC(context)。零分布的做法：在场次内打乱 full 特征的行，标签和 context 保持不动，重复 1000 次（seed=17），整个嵌套 LOSO 每次都重跑。p 值公式和 §4 相同。
- 结论的写法：只有增量检验显著（p < 0.05），并且 context+full 的 AUC 高于 identity，才能说"画面有增量信息"。

### 7.2 特征来源审计（不看标签）

- 每条样本逐帧计算：人脸框面积和中心的帧间跳变（镜头切换或推拉）、人脸数量变化、头部俯仰（低头会被误读成"闭眼"）、手部检出的连续性。
- 预先定好的标记：任意相邻两帧人脸框面积比超过 1.5 或小于 1/1.5，或者中心位移超过框宽的 0.5，记为 `camera_cut_or_zoom`；出现 2 张以上的人脸记为 `multi_face`；头部俯仰超过 25° 的帧占 30% 以上记为 `head_down`。
- 敏感性分析：排除有任意标记的样本，再跑一遍同样的协议。标记只依据特征和画面，生成时不读标签。

### 7.3 推筹码动作窗口（次要分析）

- 新窗口策略 `bet_motion_v3`：从起点 t 往前 5 秒，到"可见推筹码动作结束"的保守上界为止，并且必须早于任何对手的回应、下注额图形或字幕出现。超出部分不截取；不满足条件的样本不进这个分析。
- 帧率仍是 5fps，帧数因样本而异。特征仍是 169 个，`timing_duration` 取实际长度，并且**不进模型**。
- 风险：画面里的筹码量可能透露下注大小。所以这个分析只和 7.1 的 context 对照一起报告，结论按 7.1 的标准写。
- 动作结束时间要人工逐帧复核，复核方式和 v2 的模型视图复核相同。
